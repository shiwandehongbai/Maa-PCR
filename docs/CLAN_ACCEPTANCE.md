## 开场与账号绑定

当前无轴流程保留 SET、AUTO 和速度继承，只调整与作业不同的项。正常流程不例行进入设置页，不临时关闭或恢复继承。同一有效 Owner／设备连接实际核对一次玩家 ID，连续槽位复用绑定；切号、重连或来源失效后重核，不增加每刀个人记录检查。

普通 90 秒挑战和模拟在首次暂停时读取实际剩余秒数，并在本次开战内冻结。五人、目标、模式、SET、AUTO 和速度均须明确，每次修改后读回全队及暂停秒数。全部设置匹配时不切换；有差异时须证明受影响角色尚未首次 UB。

标准 90 秒普通挑战和模拟在 1:24 之前不会首次 UB。同一有效 Owner 的首次暂停读到 85～90 秒时，按已确认规则核验；1:24 及之后、短补偿不套用。没有统一两秒、零伤害或零 TP 前置。

可选 UB 自动解除策略只读取当前设置页，不导航或修改选项。策略默认未知，不阻断全匹配。满足同一 Owner、真实策略读回及本次开战条件时，才可作为另一项首次 UB 证据；单张 TP、伤害或开关画面不能自行补证。

旧待恢复记录继续保留。原账号明确 Start 后，只有真实现值已等于记录原值，才凭读回结账；现值冲突则停止。Stop、断线或页面未知后不继续输入，原战斗未决先阻断。

## 资料、消费和结果

账号资料沿用 24 小时有效期，不改写采集时间。解锁星级 `rarity` 不能代替出战星级 `battle_rarity`。游戏内手动改星后须重新同步并保存确认；协议同步可能使客户端断线，应重新进入后再核验。

正式消费前重新读取账号、游戏日、CP、普通次数、补偿库存和具体 Boss 实例，并取得对应消费授权。普通次数授权不能扩展为补偿消费授权。

普通 90 秒、全自有且实际补偿库存为空时，只走一次 `observe → prepare → execute`。同一有效 Owner、连接、账号和游戏日内，期间未发生消费、状态未知或重连时，复用原库存收据及 `observed_at`。实际目标页核对 CP、次数、Boss 和阶段，编队末尾核对实际五人、星级及模式。

`prepared_at` 单独记录真实准备时刻。最终 Start 和首次暂停按它核验 60 秒时效，原库存观察时间保持不变。补偿、非空库存和支援仍沿用原规则。

已知伤害先写 Journal，再返回。返回失败保留伤害并停止；未知结果不重新开战。只有完整证据证明输入没有发送，才登记为未消费。程序外人工出刀经事实确认后单列为 `observed_external`。已有 intent 的人工恢复沿原记录结账，保留人工介入标记，不计为自动验收。

补偿流程已通过本次全自有、单库存的正常 GUI 全程验收。程序使用同一 Boss 和原阵容，开场暂停、调整 SET、恢复并打完，不设置补偿开场时间或首次 UB 证明门槛。Boss 不可打或队伍不符时停止并交回玩家，不自动更换目标。后续执行仍须核对实际库存、队伍、Owner、目标实例和对应消费授权。

补偿以游戏实际发放及绑定队伍为准。同一 Boss 暂不可打时保留补偿，短补偿不自动截断完整秒数轴。
