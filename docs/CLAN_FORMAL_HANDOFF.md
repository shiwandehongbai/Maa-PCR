## 本轮实现

账号入口使用原窗口的账号专用呈现，隐藏旧攻略页和五人保存栏。首屏保留资料摘要、刷新和使用并返回；高级资料收起导入、清空、手填及原始字段。刷新成功已保存缓存，复用不更新时间。返回公会战保留编辑，使旧作业和正式确认失效；不自动开始。

公会战按账号、作业、五人和三刀排列。已选作业显示摘要，来源、目标及校准按需展开，正式确认位于三刀区域。当前模式单独显示可用性和阻断原因。

正式无轴作业使用独立 `daily.execution.opening`、正式暂停及 HUD 读回，固定 2 倍速。GUI 模式文件和作业／三刀／执行请求仍为 version 1。旧正式 1 倍配置可读，必须明确重新确认并保存 2 倍，不能直接 Start；Python 不新增正式速度请求字段。

正式和补偿不进入模拟 `auto_battle` 链。开场绑定原 intent、action、队伍及页面；按实际角色 ID 逐次设置 SET／AUTO，核对冻结秒数，恢复后核对 HUD。补偿起始时间来自真实库存和 `action.start_seconds`，不能用模拟 90／89 秒代替，未取样的动画扣秒分支继续拒绝。可选 `opening.start_seconds` 默认只覆盖 90 秒；明确缺补偿能力或未覆盖该起始秒数时保留补偿，继续其他主刀，未知与损坏仍停止。

继承使用正式独立 Journal 记录原值。准备失败在消费 intent 前停止；确认伤害及消费后先结账，再恢复。Stop、断线或未知时不追加输入。原账号下一次明确 Start 才处理待恢复记录；旧未知结果先阻断。

1. 先核对 Git、任务记录和当前候选的源码／Core 摘要。有效证据不重复执行；读取真实账号、游戏日、CP、普通次数、补偿库存和页面。

4. 普通结算、补偿发放、原队伍绑定及补偿消费分别验收。同号 Boss 没有新实例证据时保留补偿，继续其他可用主刀；短补偿不裁剪完整轴。
