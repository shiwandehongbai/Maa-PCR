# 黎明界上游差距补齐

本轮按上游固定提交 `b809b196988b019571caf5679ccf8d7ebb7f072d` 补齐 11 组差距，覆盖复活后继、商店规则及下述九项。当前为本地源码改动，尚未发布，也没有覆盖现用安装。上游 Android 的交互按 Windows 与 Maa 的运行方式适配。

## 遗物复活后继

“星辉吐息”等效果改判胜利后，游戏仍可能显示“战斗失败”，但右下方变为“下一步”，没有“结束”按钮。

程序现在同时核验失败标题、伤害报告、下一步和同帧按钮颜色布局，再将结果记录为独立的 `revived`。它不增加失败次数、重试次数或失败阵容。只有本助手刚完成的战斗能推进这条后继；点击前会重新核对布局。实际到达遗物结果后，再沿用原结果关闭与地图读回。整局通关仍需原终态校验。

普通三按钮战败、变暗弹窗、缺少必要文字或身份不匹配均不能进入复活分支。新增的页面读取仅在识别到战败页后执行。

参考：[两按钮布局识别](https://github.com/wbero/limingjie-assistant/blob/b809b196988b019571caf5679ccf8d7ebb7f072d/android/app/src/main/java/com/landosol/toolbox/labyrinth/vision/LabyrinthBattleFailureRecognition.kt)、[会话中的推进与重试区分](https://github.com/wbero/limingjie-assistant/blob/b809b196988b019571caf5679ccf8d7ebb7f072d/android/app/src/main/java/com/landosol/toolbox/labyrinth/LabyrinthEntryRecognitionSession.kt)。

## 商店规则

默认仍在第四区节省金币。当玩家启用刷新，并把起始区域设为第四区或更早时，第四区会按配置购买和刷新；关闭购买或刷新时保留原有行为。

完整的三个按钮已确认不可购买，或三格都能确认是职能印记时，可以恢复本轮遗物售罄状态。标题、价格或购买条件不足的商品不会因此获得购买资格。刷新按当前帧实际报价核验（实跑为第一次 300、第二次 600；第 2 次后按钮变暗，社区攻略与主数据均指向同一商店最多刷新 2 次，实现以按钮亮度为准而不写死次数），并核验刷新按钮内侧亮度，报价、确认与扣费仍分别核验，不重发已结算操作。

刷新按钮未识别与明确不可刷新分开记录：按钮位置或文字无法识别时只读等待；按钮已变暗（本店刷新次数用尽或不可用）时不点击，直接购买可确认印记或离店。刷新点击后若确认弹窗未出现、且货架、余额与报价均未变化，判定为刷新不可用并继续同店流程；余额恰好减少报价时按刷新已生效记录；页面未知或无法读回仍保持停止。该恢复不重发已发出的点击，也不把可选优化动作升级为整批中止。货架仍有未定商品且没有可先购买的可信遗物时，继续只读观察，沿用原有 30 秒预算和更短父预算。等待期间不买印记、不刷新、不离店；超时、停止和未知结果保持停止，不补发操作。

参考：[上游商店决策](https://github.com/wbero/limingjie-assistant/blob/b809b196988b019571caf5679ccf8d7ebb7f072d/android/app/src/main/java/com/landosol/toolbox/labyrinth/LabyrinthShopPolicy.kt)。

## 幽灵领主编组

幽灵领主默认按魔法伤害评估前排；明确指定敌方伤害类型时使用指定值。队伍优先降低前排 300 站位范围内的额外成员和多坦克风险，再比较评分。首次编组、失败换人和第二败补治疗共用规则，仍排除已失败阵容并保留遭遇核心要求。缺少站位的成员按未知风险处理。

## 特别装备

策略设置可启用自动装备，并选择普通战斗、EX 和 Boss；默认关闭。队伍确认后才打开特别装备，依次核对主面板、自动装备确认面板和变更后的确认按钮。无变更或按钮不可用时取消并返回；确认穿戴后重新核对队伍，才允许开战。Boss 每个有成员的队伍单独处理。

两个面板同时核验标题、结构和模板，避免把相似的遗物系列面板当成装备。最终确认与取消只发送一次；结果未知会停止。已完成且队伍未变的轮次可复用，不能复用未确认的操作。

## 游戏数据库

默认在任务启动时后台检查公开 CN 游戏数据库，也可关闭自动更新。下载文件经过受限 HTTPS、SHA256、SQLite 完整性及所需数据表校验后才原子切换；失败保留可用旧缓存。每次任务使用启动时冻结的事实，新下载在下次任务启用。

当前动态事实用于角色站位和物理／魔法攻击类型；个人评分、主观评分、原有战斗估计和头像模板保留。无法可靠辨认的字段继续使用原有静态事实。缓存位于 `data/labyrinth/master-cn`，不进入源码交付。

## 渠道服与账号库

支持 Bilibili、小米、华为、vivo、OPPO、九游、4399、MuMu 和应用宝。B 服使用原登录方式，渠道服使用该渠道授权所得 UID 与 `access_key`。游戏玩家 ID 仍为个人简介中的 ID。协议网关、请求标识、客户端包名及安装版本均随服务器绑定；未知渠道拒绝启动。

4399、MuMu 和应用宝在协议登录前确认客户端关闭，恢复游戏时再核对冷启动标题。九游提示按明确的登录历史结构处理，临时竖屏只在原预算中等待。非 B 渠道使用独立账本，所有渠道共享运行占用锁，不能把另一服务器的旧局当作续局。

界面可新增、命名、切换和删除账号。各账号分别保存服务器、玩家 ID、凭据和任务策略。旧单账号配置首次读取时保留，保存时迁入账号库；凭据继续使用 Windows 当前用户加密。写入检查文件占用及并发更改，失败保留原配置。一次只执行当前所选账号。

## 个人评分

评分编辑器支持姓名、版本和角色 ID 搜索、头像、仅查看已修改角色、单项恢复和全部恢复。手动评分为 0–100 整数，保存后才应用；取消丢弃草稿。既有未知角色键及小数评分在未明确修改时原样保留，保存失败会恢复内存值。

## 暂停、继续和响应节奏

运行中可暂停和继续。已开始的输入先完成确认和记账，再报告暂停；继续使用同一进程、账号、队伍和计数。暂停期间不派发新操作，停止可解除暂停。已确认的暂停时间不计入业务等待预算；继续后仍使用原有页面和输入守卫。该功能不增加任意崩溃后的中途接管能力。

响应节奏可选 300 或 500 毫秒，默认 300。启动后按快照控制观察频率，输入节点的校准等待和动作上限保持原值。

## 运行诊断

任务运行时每 10 秒记录进程 CPU、进程内存、宿主内存及捕获状态，最多保留一小时。事件诊断记录识别耗时、稳定性、按钮拒绝原因和选择结果，输入记录回调耗时。诊断不保存 OCR 原文、图片或凭据；现有故障截图机制单独保留。日志 ZIP 通过固定路径白名单收集四个诊断文件，任务结束后停止采样。

## 编组名单收窄（本地差异）

编组/Boss 队伍页只显示本局已加入的角色：开局三人，之后每次“角色加入”读回成功后追加，`prepare_team` 在加入尚未读回时拒绝开始，所以进入编组页时名单完整。程序现在把这份名单作为识别候选的硬边界：调用方提供本局名单时，`IconMatcher.match` 的 fine 阶段只在名单内比较；名单与图鉴无交集时回退全库顺序，未知名单不会因此获得身份。

上游的 roster override 是软收窄：只有全库 coarse 第一与名单内第一相差小于 0.08 才收窄。本地改为硬收窄的依据是 2026-11-01 实跑——EX 编组加入带助战角标的 1215 时，点击确认帧里名单外的若菜(冬日) 1387 以 0.5376 对 1215 的 0.4931（差 0.0445，低于 0.045）压过真卡，点击没有发出，整批以 `native_input_not_sent` 停止；同一局名单人数与编组页卡数在 3/3、7/7、14/14、15/15 四个时点一致。coarse 仍按全图鉴计算，属性过滤、稳定排序、变体合并、置信度与对手分差阈值均未改。

公开回归与保存帧回放见 [LABYRINTH_ROSTER_MATCHING.md](LABYRINTH_ROSTER_MATCHING.md)；回放不代替实机验收。
