# 公会战作业

“公会战”是第三个配置，内部标识为 `pcr-agent-v1`，与“日常&扫荡”“黎明界bot”共用原 Start、Stop、Owner 和 Maa。

R67 本地候选已开放内容版本 `202610141448`、第 2 阶段（B）的全自有纯 AUTO 模拟。第三 Boss 和已败第五 Boss 均由真实 GUI Owner 完成编队、开场核验、伤害读回和返回。入口可从主页、冒险、团队战大厅及 Boss 详情启动，已击败后的宝箱仍可进入模拟。完整范围见[分项验收](CLAN_ACCEPTANCE.md)。

使用时先选作业，再选用本队账号资料，核对五人、出战星级、SET 和 AUTO 后保存。当前只开放全部自有；借人身份尚未校准。出战星级来自已绑定资料的 `battle_rarity`，资料有效期沿用 24 小时。手动改星后须重新同步并保存确认；同步可能使游戏客户端断线，重新进入后再开始模拟。

秒数轴已有离线切换与停止保护，但真实耗时未达要求，保持关闭。正式三刀和补偿已接入 `observe → prepare → execute` 适配器及离线检查；当前随包资料不授予这两项执行能力，不能消耗正式次数。

下方保留截至 2026-10-22 的配置与识别研究。旧检查数量、空校准清单及开放前状态仅为历史记录；当前能力以随包校准和本页分项验收为准。

## 历史：完整会战助手的开放前版本

默认模式仍是单次模拟。正式三刀模式可预览完整三目标并单独确认；当前正式入口会在读取设备或分配控制器前拒绝，Python 入口也独立拒绝，不会创建正式意图。切换模式不是执行资格。独立候选只使用合成资料做配置检查，不携带真实账号或旧账。

执行模式保存失败时，面板清除模式选择并取消执行确认，需重新打开读取磁盘状态。当前队伍草稿和其他窗口已保存的内容保留。

模拟已接入受控校准加载，只接受安装内固定清单及摘要链绑定的本机保存帧资源。玩家作业不能提供校准路径或自行标记已验证，离线回放不构成真实输入资格。当前校准清单为空，在构造会战端口前保存停止报告。真实入口、编队、支援、HUD、伤害和结果返回仍待真帧适配；生产保持原 MaaOCR，秒数轴未启用。

模拟的伤害确认与返回目标页分开记录。伤害和设置可信时先按原 Journal 结账，再尝试一次经校准的返回；返回失败保留已知伤害，总报告停止，不补点或重开本次模拟。以后新的明确 Start 仍须重新核对来源和新鲜目标，未知目标不追加新意图。

正式批次的内部离线实现使用独立 Journal，冻结账号、期次、游戏日、三目标及确认摘要；同日已有意图后不能换计划。未完成主刀按槽位扫描，明确不可用才跳过，未知状态停止。尾刀按来源槽位及库存号排序，只有实际新实例和来源结算后的刷新证据匹配才建议使用。三次主刀均结账且普通次数确认为 0 后，仍有补偿才提醒未用尾刀。全部目标不可用时结束本轮，不后台等待。

再次 Start 只接续本助手记录，不重复已结账主刀；首版不接管外部手动出刀。原批次未知永不重发，新游戏日只在新的明确 Start 和实际重置观察通过后建立新批次。尾刀不按击杀或余时公式生成，不自动裁剪完整战斗轴。以上批次逻辑目前仅由内部合成端口验证，生产缺少正式页面适配器，正式及补偿输入继续关闭。

每次可信结算写入账本后，报告同步保存实际剩余次数。随后返回失败或停止时，仍保留这次已验证的次数和伤害；无效结算不能覆盖此前可信的观察。

独立包沿用现有 portable 构建和锁定依赖，已把视频导入脚本纳入复制及必需文件检查。完整包与原候选分别保存，不能用旧一次性 DLL 同步脚本覆盖原候选。每阶段的构建、跨语言请求、故障恢复和实际界面证据登记在原交接及 `.runtime/clan-agent-20261020/full-assistant/`。

## 导入和保存

1. 切换到“公会战”，核对原渠道设置。首版只接受 B 站账号资料。
2. 粘贴完整 B 站视频链接并获取，或打开已生成的 `bundle.json`。按分 P、套餐和队伍选择作业。
3. 对照完整原图和队伍局部图，核对期次、阶段、周目、BOSS、五人形态、战斗星级、SET、AUTO 与支援。识别候选没有自动确认；不确定字段须明确填写。星级留空时使用原账号缓存实值，不能据此保证符合作者星级。
4. 选择原账号缓存，点击“核对五人和操作并保存”。练度、EX 和强化差异只作提醒。修改作业或更换账号后需要重新确认。

每期视频保存独立材料，不将九月队伍写入执行代码。原图、BV、分 P、CID、时间点及摘要随作业保存。`agent-guide-review.json` 只保存 Agent 当前选择；账号、角色目录和公开攻略库共用原目录，不复制或迁移旧账号文件。原缓存超过 24 小时会阻止执行，本模块不会登录或刷新采集时间。

离线命令使用工程现有 Python：

```powershell
python -X utf8 -B scripts/prepare-clan-guide.py --video-url 'https://www.bilibili.com/video/BV1Rbh86XEsq/' --output '.runtime/clan-video-new'
```

输出目录必须尚不存在。默认获取全部分 P；`--page 2` 只处理指定分 P。获取和取图复用原实现，未新增 yt-dlp 或浏览器登录依赖。获取失败保留材料和错误，不覆盖已有作业。

## 支援和秒数轴

“全部自有”要求五人明确持有。“缺谁借谁（qsjs）”在五人齐全时用本人，缺一名时借该角色；缺多名或没有匹配支援则停止。指定支援只借指定的本队角色，其余四人须明确持有。同角色按作业星级匹配，再按游戏列表顺序选择可用项，不替换角色。只有根据缺行推断“缺谁”时需要完整名单，部分缓存中未知持有不能当作缺少。

纯 AUTO 作业的秒数轴留空。首版只接受明确剩余秒数，每秒一行，同秒多项操作写在同一行：

```text
80 | 不变 | 100101=关；100201=开
59 | 关 |
```

第一列为剩余秒数；第二列为 AUTO（不变、开、关）；第三列为角色编号或完整角色名及 SET 状态。秒数必须严格递减。程序按真实角色位置只改不符项，每次操作后读回全队。漏秒、未知状态、6002 断线或 Stop 后不补点；没有读取间隔和整组操作耗时证据的轴不可执行。

## 单次执行与记录

开放后，仍须另行确定具体模拟目标并完成真实页面校准。程序必须核对实际账号、期次、阶段、周目、BOSS 和“模拟战”标记；关闭页面只报告不可执行。正式出刀入口当前仍拒绝生产执行。

一次 Start 只安排一次模拟。会战记录复用原 `Journal` 类，保存在独立业务目录 `.runtime/clan-battle-simulation-work/ledger`，绑定作业、账号、目标和实际五人／支援。完整设置及伤害读回后才能结账。结果不明保留未决，阻止再次 Start；不清账、不自动重试，不套用原深域每关三次计数。实际伤害不要求等于作者参考值。

## 一天三刀目标与补偿预设

在“核对五人和操作并保存”下方展开“一天三刀目标（仅离线预设）”。将当前已核对队伍依次设为第 1、2、3 刀。可以先保存部分目标；凑齐后点击“核对完整三刀预设”。三队须属于同一服务器、账号和期次。重复占用的自有角色会逐项提示，完整核对会停止；程序不替换角色或组合队伍。

`clan-battle-daily-plan.json` 只保存原作业引用及核对摘要。更换原图、作业、账号缓存或确认后，需要重新核对对应目标。预设不保存“已出几刀”、剩余次数或补偿库存，也不随 05:00 清除作业模板。当前 Start 仍只模拟面板选中的一队一次，不会连续打三刀。

点击“载入第 N 刀到当前模拟队”可恢复该槽位已核对的队伍。程序先复核原图、账号缓存、确认及文件版本，再沿原锁和预期摘要保存当前选择，写后读回成功才更新面板；保留其他队伍的已保存核对。可见队伍、磁盘当前队伍和 Start 读取的计划须一致。资料过期、原件变化或并发修改会拒绝载入；写后读回失败会取消面板确认，需重新打开核对。“放弃编辑并重开”会同时刷新当前队伍和三刀摘要。

当前游戏每累计 300 CP 解锁一次普通挑战，每天最多 3 次；CP 是累计进度，不能按每次开战扣减 300 核账。挑战次数与 CP 的日界为 05:00，实际消费仍须读取页面核对。补偿时间挑战另作区分，不能当成新增普通次数。历史活动规则参见[国服官方团队战公告](https://www.bilibili.com/opus/1158728918930292785)。

离线策略按你的要求保留：只有实际读到补偿资格，且同编号 BOSS 本次可用、周目和阶段符合原作业时，才建议先用补偿；目标未出现则保留，继续下一主刀。只有 3 次主刀均实际结算、消费事实已核实，且游戏显示普通剩余次数为 0，才提醒仍有未用补偿。任何未知结果先停止，不重发。

上述策略目前由 `clan_battle_daily.py` 用合成记录回放，始终返回不可执行，尚未连接正式／补偿战斗入口。没有从 BOSS 死亡生成补偿，也没有硬编码余时公式。当前国服补偿生成、使用阵容／支援、阶段切换及日界处理，须用开放后的实际页面核对。
