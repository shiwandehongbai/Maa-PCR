# 软件更新与恢复

Maa-PCR 将界面、业务代码、资源和运行时作为一个版本，从 `shiwandehongbai/Maa-PCR` 的稳定 Release 更新。以安装清单的 revision 判断新旧，不比较 MFAAvalonia 组件版本。不需要 GitHub 账号、Token 或 Git 客户端。

## GitHub 自动检查和安装

在软件更新页开启“启动时检查稳定版”，软件启动后会检查更新。也可点击“检查更新”。发现新版本后，点击“下载并安装”，确认后下载、校验并安装。启动检查不会静默安装或启动游戏任务。

下载时显示进度，可以取消。网络不可达或下载失败时，当前安装继续保留，可稍后重试或导入本地更新包。“更新代理”只用于在线检查和下载，可选“跟随系统”（默认，使用 Windows 系统代理）、“自定义代理”（填写 `[<用户名>:<密码>@]<主机>:<端口>`）或“无代理”；本地校验、安装和恢复不依赖代理设置。暂不接入 CNB 或其他下载源。

更新检查直接读取官方 Release 的 `releases/latest/download/update-index.json`，不调用 GitHub REST API，避免共享出口 IP 的匿名 API 额度耗尽。下载地址固定在本仓库的清单版本标签下，检查与下载沿用界面已有的互斥控制。HTTP 错误、限流及网络不可达会给出具体提示。

更新索引明确绑定附件大小、SHA256 和目标清单；精确基线补丁优先，否则使用完整运行包保留数据升级。

## 本地更新包导入

在软件更新页点击“导入更新包”，或将一个 ZIP 拖入主窗口。选择从可信 Release 下载的完整运行包，或与当前安装精确匹配的补丁。外层交付 ZIP 包含运行包、源码和说明，需先取出其中的运行包或补丁 ZIP。

软件先校验整个包，再显示当前版本、目标版本和包类型，确认后才准备外置安装。安装前会再次校验，拒绝校验后被更改的包。关闭确认窗口等同取消，不安装。不要解压更新包覆盖安装目录。

普通更新只接受更高 revision，同修订候选替换和 R54 转 R52 仍使用各自的精确专用工具，不通过普通导入入口放宽。

## 数据保留和失败恢复

所有任务空闲后退出 GUI 和 Agent，由安装目录外的临时内置 Python 执行维护器。校验新程序后只重新打开 GUI，任务不会自动继续。模拟器和游戏不会被强制结束。设置、任务顺序、账号数据、日志、账本及非程序文件不覆盖。

R38首次升级使用单独的R38→R39引导更新包：先正常退出GUI/Agent，解压引导包并运行其中的`first-update.bat`，选择原安装目录。入口会校验精确R38基线和包内补丁，暂存外置维护器，等待引导进程退出后安装。不要通过R38旧的`导入补丁包.bat`替换正在使用的Python，也不要直接解压覆盖安装目录。完成这次引导升级后，后续更新直接在软件内操作。

下载失败/取消可重试，不影响现有安装。安装过程中不要删除`.runtime/player-maintenance`或临时更新工作目录；它们包含回滚与恢复证据。发现未完成更新时，先使用恢复入口，核验完成前禁止执行游戏任务。未知文件冲突不自动覆盖，保留失败报告后再处理。

R38旧维护器生成的不完整更新记录若缺少恢复所需信息，不自动猜测修复。保留原目录和备份，使用已校验的完整包外置维护器诊断；禁止清除更新标记来绕过阻止。

SHA256用于损坏和版本绑定校验，不是独立发布者签名。首版信任GitHub仓库与HTTPS，不做静默安装、CDN或多跳补丁。
